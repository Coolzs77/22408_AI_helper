### 2.4 面试准备核心

#### 必须准备的内容（按重要性排序）

**1. 毕设详细介绍（最重要！占面试很大比重）**
准备时间：每天至少1小时，反复演练

准备内容：
```
A. 开场介绍（2分钟）
   - 研究背景：为什么选这个课题？
     "随着智慧城市发展，红外成像在夜间监控中应用广泛，
      但传统可见光算法在红外图像上表现不佳..."
   
   - 研究意义：解决什么实际问题？
     "本研究针对红外图像低对比度、弱纹理的特点，
      设计轻量化AI算法，可部署在低成本边缘设备..."

B. 技术方案详解（5-8分钟）
   必须能清晰讲解：
   
   1) 整体架构（参考开题报告图4.1）
      - 数据输入层：FLIR数据集，为什么选这个数据集？
      - 算法处理层：YOLOv5检测 + 多目标跟踪
      - 嵌入式部署层：RV1126平台，为什么选这个芯片？
      - 性能评估层：mAP、MOTA等指标
   
   2) 检测模块（YOLOv5）
      - 为什么选YOLOv5？（速度与精度平衡）
      - 网络结构：Backbone、Neck、Head分别做什么？
      - 轻量化改进：
        * 骨干网络替换（Ghost-C3、Shuffle-C3）
        * 损失函数优化（CIoU→SIoU/EIoU）
        * 注意力机制（CBAM、CoordAttention）
      - 每个改进解决什么问题？效果如何？
   
   3) 跟踪模块
      - 对比三种算法：DeepSORT、ByteTrack、CenterTrack
      - 各算法原理：
        * DeepSORT：卡尔曼滤波 + ReID特征匹配
        * ByteTrack：双重关联，高低置信度分别处理
        * CenterTrack：中心点偏移预测
      - 为什么最终选择XX算法？
      - 在红外图像上的特殊处理
   
   4) 嵌入式部署
      - 模型转换流程：PyTorch→ONNX→RKNN
      - INT8量化：如何保证量化后精度？
      - C++实现：RKNN API使用
      - 性能优化：如何达到25fps？

C. 实验结果（3分钟）
   准备数据图表：
   - 检测性能：mAP@0.5达到75%以上（目标值）
   - 跟踪性能：MOTA达到60%以上
   - 系统性能：25fps实时处理
   - 消融实验：每个改进模块的贡献度

D. 遇到的困难与解决方案（2分钟）
   准备3-5个具体案例：
   - 问题：红外小目标漏检严重
     解决：引入注意力机制，改进特征金字塔
   
   - 问题：跟踪时身份切换频繁
     解决：对比多种算法，选择适合红外场景的方案
   
   - 问题：模型量化后精度下降
     解决：使用红外图像作为校准数据集，调整量化参数

E. 创新点（1分钟）
   - 针对红外图像特点的轻量化设计
   - 多种跟踪算法的系统对比研究
   - 国产芯片RV1126的完整部署方案

F. 未来工作（1分钟）
   - 更多红外数据集测试
   - 更先进的跟踪算法（如OC-SORT）
   - 多模态融合（可见光+红外）
```

**下午 14:00-17:00【毕设-实现Ghost-C3】**
- 14:00-15:00 学习Ghost Module原理
  * 阅读论文：GhostNet: More Features from Cheap Operations
  * 理解核心思想：
    ```
    传统卷积：直接生成n个特征图，计算量大
    Ghost Module：
      1. 用少量卷积生成m个本征特征图(m < n)
      2. 对每个本征特征图做cheap操作生成ghost特征图
      3. 拼接得到n个特征图
    
    计算量降低：约为传统卷积的1/2
    ```
  
- 15:00-16:30 编写Ghost-C3代码
  * 在 models/common.py 中添加：
  ```python
  class GhostConv(nn.Module):
      def __init__(self, c1, c2, k=1, s=1, g=1, act=True):
          super().__init__()
          c_ = c2 // 2  # hidden channels
          self.cv1 = Conv(c1, c_, k, s, None, g, act)
          self.cv2 = Conv(c_, c_, 5, 1, None, c_, act)
      
      def forward(self, x):
          y = self.cv1(x)
          return torch.cat([y, self.cv2(y)], 1)
  
  class Ghost_C3(nn.Module):
      # C3 module with Ghost convolutions
      def __init__(self, c1, c2, n=1, shortcut=True, g=1, e=0.5):
          super().__init__()
          c_ = int(c2 * e)
          self.cv1 = GhostConv(c1, c_, 1, 1)
          self.cv2 = GhostConv(c1, c_, 1, 1)
          self.cv3 = Conv(2 * c_, c2, 1)
          self.m = nn.Sequential(*(GhostBottleneck(c_, c_) for _ in range(n)))
      
      def forward(self, x):
          return self.cv3(torch.cat((self.m(self.cv1(x)), self.cv2(x)), 1))
  ```

- 14:00-15:00 学习ShuffleNet原理
  * 阅读论文：ShuffleNet: An Extremely Efficient CNN for Mobile Devices
  * 理解核心思想：
    ```
    问题：分组卷积导致组间信息不流通
    解决：通道混洗（Channel Shuffle）
    
    步骤：
    1. 分组卷积
    2. 通道重排：将各组特征交叉混合
    3. 下一层分组卷积能看到上一层所有组的特征
    ```
  
- 15:00-16:30 编写Shuffle-C3代码
  * 在 models/common.py 中添加：
  ```python
  def channel_shuffle(x, groups):
      batch, channels, height, width = x.size()
      channels_per_group = channels // groups
      x = x.view(batch, groups, channels_per_group, height, width)
      x = torch.transpose(x, 1, 2).contiguous()
      x = x.view(batch, -1, height, width)
      return x
  
  class ShuffleConv(nn.Module):
      def __init__(self, c1, c2, k=1, s=1, g=1, act=True):
          super().__init__()
          self.conv = Conv(c1, c2, k, s, None, g, act)
          self.groups = g
      
      def forward(self, x):
          x = self.conv(x)
          return channel_shuffle(x, self.groups)
  
  class Shuffle_C3(nn.Module):
      # C3 module with Shuffle convolutions
      def __init__(self, c1, c2, n=1, shortcut=True, g=1, e=0.5):
          super().__init__()
          c_ = int(c2 * e)
          self.cv1 = ShuffleConv(c1, c_, 1, 1, g=2)
          self.cv2 = ShuffleConv(c1, c_, 1, 1, g=2)
          self.cv3 = Conv(2 * c_, c2, 1)
          self.m = nn.Sequential(*(ShuffleBottleneck(c_, c_) for _ in range(n)))
      
      def forward(self, x):
          return self.cv3(torch.cat((self.m(self.cv1(x)), self.cv2(x)), 1))
  ```

- 14:00-15:30 学习IoU系列损失函数
  * IoU (Intersection over Union)
    ```
    IoU = (A ∩ B) / (A ∪ B)
    问题：当两个框不相交时，IoU=0，梯度为0，无法优化
    ```
  
  * GIoU (Generalized IoU)
    ```
    考虑最小包围框，解决不相交时梯度为0的问题
    ```
  
  * DIoU (Distance IoU)
    ```
    考虑中心点距离，加快收敛
    DIoU = IoU - ρ²(b, bᵍᵗ) / c²
    其中ρ是中心点距离，c是最小包围框对角线长度
    ```
  
  * CIoU (Complete IoU)
    ```
    在DIoU基础上增加长宽比惩罚
    CIoU = DIoU - α * v
    其中v衡量长宽比一致性
    ```
  
  * EIoU (Efficient IoU)
    ```
    分别考虑宽度和高度的差异
    ```
  
  * SIoU (Scylla IoU)
    ```
    引入角度损失，特别适合红外目标
    ```

  * CBAM = Channel Attention + Spatial Attention
  
  * Channel Attention Module (CAM):
    ```
    1. 全局平均池化 + 全局最大池化
    2. 通过共享MLP
    3. 逐元素相加后Sigmoid
    4. 与输入特征相乘
    ```
  
  * Spatial Attention Module (SAM):
    ```
    1. 在通道维度做平均池化和最大池化
    2. 拼接后通过卷积
    3. Sigmoid激活
    4. 与输入特征相乘
    ```
  
- 15:00-16:30 编写CBAM代码
  ```python
  class ChannelAttention(nn.Module):
      def __init__(self, in_channels, ratio=16):
          super().__init__()
          self.avg_pool = nn.AdaptiveAvgPool2d(1)
          self.max_pool = nn.AdaptiveMaxPool2d(1)
          self.fc = nn.Sequential(
              nn.Conv2d(in_channels, in_channels // ratio, 1, bias=False),
              nn.ReLU(),
              nn.Conv2d(in_channels // ratio, in_channels, 1, bias=False)
          )
          self.sigmoid = nn.Sigmoid()
      
      def forward(self, x):
          avg_out = self.fc(self.avg_pool(x))
          max_out = self.fc(self.max_pool(x))
          out = self.sigmoid(avg_out + max_out)
          return x * out
  
  class SpatialAttention(nn.Module):
      def __init__(self, kernel_size=7):
          super().__init__()
          self.conv = nn.Conv2d(2, 1, kernel_size, padding=kernel_size//2, bias=False)
          self.sigmoid = nn.Sigmoid()
      
      def forward(self, x):
          avg_out = torch.mean(x, dim=1, keepdim=True)
          max_out, _ = torch.max(x, dim=1, keepdim=True)
          x_cat = torch.cat([avg_out, max_out], dim=1)
          out = self.sigmoid(self.conv(x_cat))
          return x * out
  
  class CBAM(nn.Module):
      def __init__(self, in_channels, ratio=16, kernel_size=7):
          super().__init__()
          self.ca = ChannelAttention(in_channels, ratio)
          self.sa = SpatialAttention(kernel_size)
      
      def forward(self, x):
          x = self.ca(x)
          x = self.sa(x)
          return x
  ```

    ```
    - 状态向量：(x, y, a, h, vx, vy, va, vh)

      a: 宽高比
      h: 高度
      v*: 对应的速度分量

    - 对当前帧每个检测框，提取128维ReID特征

    步骤3：级联匹配
    - 第一级：用IoU匹配高置信度检测
    - 第二级：用余弦距离匹配外观特征
    - 第三级：用匈牙利算法最优分配
    
    步骤4：更新轨迹
    - 匹配成功：更新轨迹状态
    - 未匹配检测：初始化新轨迹
    - 未匹配轨迹：标记为丢失，连续丢失超过阈值则删除
    
    输出：当前帧每个目标的ID和位置
    ```

- 14:00-15:30 ByteTrack算法原理学习
  * 阅读论文：ByteTrack: Multi-Object Tracking by Associating Every Detection Box
  
  * 核心创新：双重关联策略
    ```
    传统方法：只用高置信度检测框进行匹配
    问题：遮挡时，目标的检测置信度降低，被丢弃，导致轨迹中断
    
    ByteTrack解决方案：
    
    步骤1：第一次关联
    - 用高置信度检测框（score > 0.6）与轨迹匹配
    - 使用IoU作为匹配指标
    - 匈牙利算法分配
    
    步骤2：第二次关联  
    - 用低置信度检测框（0.1 < score < 0.6）
    - 与第一次未匹配的轨迹进行匹配
    - 找回被遮挡的目标
    
    步骤3：轨迹管理
    - 匹配成功：更新轨迹
    - 新检测：初始化轨迹
    - 未匹配轨迹：保留一段时间
    
    优势：
    1. 不需要外观特征，计算效率高
    2. 有效处理遮挡情况
    3. 适合红外图像（外观特征不明显）
    ```
  
  * 与DeepSORT对比：
    ```
    | 特性 | DeepSORT | ByteTrack |
    |------|----------|-----------|
    | 外观特征 | 需要ReID网络 | 不需要 |
    | 计算复杂度 | 较高 | 较低 |
    | 遮挡处理 | 外观特征 | 低置信度检测 |
    | 适用场景 | 纹理丰富 | 纹理弱（红外）|
    ```

- 14:00-15:30 CenterTrack算法原理学习
  * 阅读论文：Tracking Objects as Points
  
  * 核心思想：将跟踪转化为关键点检测
    ```
    传统方法：检测 + 数据关联（两阶段）
    CenterTrack：端到端直接预测跟踪结果
    
    网络输入：
    - 当前帧图像 I_t
    - 前一帧图像 I_{t-1}
    - 前一帧的heatmap（中心点热图）
    
    网络输出：
    - 当前帧中心点热图
    - 目标尺寸
    - 中心点偏移量（相对于前一帧）
    
    跟踪过程：
    1. 检测当前帧的目标中心点
    2. 根据预测的偏移量，关联到前一帧的目标
    3. 直接得到目标ID
    
    优势：
    4. 端到端训练
    5. 避免复杂的数据关联
    6. 速度快
    
    劣势：
    7. 对快速运动目标效果差
    8. 长时间遮挡后恢复能力弱
    9. 需要训练（不像DeepSORT/ByteTrack可以即插即用）
    ```
  
- 15:30-17:00 三种跟踪算法对比总结
  * 制作对比表格：
    ```markdown
    | 算法 | 原理 | 优势 | 劣势 | 适用场景 |
    |------|------|------|------|----------|
    | DeepSORT | 卡尔曼滤波 + ReID | 遮挡恢复好 | 计算量大，需要外观特征 | 可见光，纹理丰富 |
    | ByteTrack | 双重关联 | 简单高效，不需要ReID | 长时间遮挡处理弱 | 红外图像，实时性要求高 |
    | CenterTrack | 端到端预测偏移 | 速度快 | 快速运动和长遮挡效果差 | 目标运动平缓 |
    ```
  
  * 预判：ByteTrack最适合红外场景
    - 理由1：红外图像外观特征不明显，DeepSORT的ReID优势不大
    - 理由2：ByteTrack的双重关联能有效处理检测不稳定问题
    - 理由3：计算效率高，有利于嵌入式部署

  * TCP连接管理（重点！）：
    - 三次握手（建立连接）：
      ```
      Client                Server
      SYN=1, seq=x    →
                      ←  SYN=1, ACK=1, seq=y, ack=x+1
      ACK=1, ack=y+1  →
      
      为什么需要三次而不是两次？
      - 防止失效的连接请求到达服务器
      - 确认双方的发送和接收能力
      ```
    
    - 四次挥手（释放连接）：
      ```
      Client                Server
      FIN=1, seq=u    →
                      ←  ACK=1, ack=u+1
                      ←  FIN=1, seq=w, ack=u+1
      ACK=1, ack=w+1  →
      (等待2MSL)
      
      为什么需要四次？
      - TCP是全双工，双方都要主动关闭
      - 服务器可能还有数据要发送
      
      为什么要等待2MSL？
      - 确保最后的ACK被对方收到
      - 防止旧连接的数据出现在新连接中
      ```
  
  * TCP可靠传输（重点！）：

- 19:00-20:30 数据库进阶
  * 事务管理（重点！）：
    - ACID特性：
      * Atomicity（原子性）：全做或全不做
      * Consistency（一致性）：保持数据一致性约束
      * Isolation（隔离性）：并发事务互不干扰
      * Durability（持久性）：提交后永久保存
    
    - 并发控制：
      * 问题：丢失修改、不可重复读、读脏数据
      * 封锁协议：一级、二级、三级封锁协议
      * 两段锁协议（2PL）
      * 死锁的预防和解决
    
    - 事务隔离级别（重点！）：
      * Read Uncommitted（读未提交）
      * Read Committed（读已提交）
      * Repeatable Read（可重复读）
      * Serializable（串行化）
  
  * 数据库设计：
    - ER图：实体、属性、联系
    - 范式理论（重点！）：
      * 第一范式（1NF）：属性不可分
      * 第二范式（2NF）：消除部分函数依赖
      * 第三范式（3NF）：消除传递函数依赖
      * BCNF：消除主属性对候选码的部分和传递依赖
  
  准备范式判断和分解的题目
